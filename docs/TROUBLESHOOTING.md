# 排障说明

| 现象 | 检查方法 |
| --- | --- |
| F9 没反应 | 确认使用 X11，并已执行安装器；运行 doctor/status 并检查桌面自启动项，确认其他软件没有占用 F9。无桌面环境的安装不会立即启动服务。 |
| 一直显示启动 | Chrome 必须已安装，扩展应已加载；核对实际扩展 ID 与 Native Messaging 配置，重新执行安装并重新加载扩展。 |
| 提示初始化或绑定 | 从扩展面板打开专用 ChatGPT 页面，登录、授权麦克风、清空草稿并绑定。 |
| 登录失效或找不到按钮 | 点击错误悬浮窗打开专用页面，先确认网页能手动听写；如网页布局变化，需要修复选择器。 |
| 没有检测到声音 | 检查系统输入设备和 ChatGPT 的麦克风权限；音量条还依赖 PipeWire/pulsectl，没有音量条不一定代表录音失败。 |
| 草稿未清空 | 没有待补填结果时，按 F8 重置旧草稿绑定，再按 F9；原页文字保留。也可手动处理专用页草稿。转写中取消后会自动隔离旧页，避免迟到结果阻塞下一轮。 |
| 得到文字却没填入 | 转写期间请保持原窗口和输入框。重新点击目标输入框后按 F8 重试，或点击错误悬浮窗／右键复制结果；核对目标软件支持 Ctrl+V。 |
| 关闭后 F9 又打开 | 右键关闭设计为待唤醒。要彻底移除 F9 监听，执行卸载。 |

## 诊断

先运行 `python3 scripts/dictate.py doctor` 和 `python3 scripts/dictate.py status`。缺少桌面会话时请从 X11 桌面终端执行。

扩展面板保留状态与最近结果。系统日志位于 `~/.cache/chatgpt-dictation/`，`timings.jsonl` 记录启动、打开页面、转写与插入的分段耗时。

需要详细诊断时，在已停止旧服务、且没有正在听写的情况下，用当前桌面终端启动：

```bash
DICTATION_DEBUG=1 ~/.local/share/chatgpt-dictation/daemon
```

调试记录写入 `daemon-debug.log`。日志、状态快照、截图可能包含转写文字和个人信息；提交公开 issue 前请检查并删去这些内容。只提供问题步骤、系统会话类型、Chrome 版本、错误文本和脱敏片段即可。

## 当前兼容性

- Wayland 尚未实现，需要另行接入输入法或系统门户。
- 普通文本粘贴可用，但不能保证恢复富文本、图片和文件剪贴板。
- 同一窗口内切换输入框、光标移动等变化不能全部通过 X11 检测。
- 终端常用 Ctrl+Shift+V，本项目默认 Ctrl+V，尚未为终端增加专用策略。
- 后台启动 Chrome 使用的命令行保活参数和网页 DOM 都可能随 Chrome/ChatGPT 更新变化。
